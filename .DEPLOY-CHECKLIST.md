# Checklist de Deploy — "Racha do Fofim" (Supabase + Render)

Use este checklist para garantir que cada etapa foi concluída corretamente antes, durante e após o deploy.

---

## ✅ PRÉ-DEPLOY (Ambiente local)

### Preparação do Supabase
- [ ] Projeto Supabase criado (`racha-do-fofim` ou similar)
- [ ] Project URL guardado (ex: `https://xxxxxxxxxxxxx.supabase.co`)
- [ ] Service Role Key guardado (aba Settings → API)
- [ ] Auth > Email/Password habilitado
- [ ] Storage bucket `uploads` criado e marcado como público
- [ ] Schema SQL (tabelas) executado com sucesso no SQL Editor
- [ ] Admin padrão (`user-admin` / `admin@racha.com` / `admin`) inserido
- [ ] Temporada padrão criada (`season-2026`)
- [ ] Configuração recorrente criada

### Preparação do código
- [ ] `npm install` rodado (novas dependências: `@supabase/supabase-js`, `helmet`, `cors`, `express-rate-limit`, `file-type`)
- [ ] `.env.local` criado com valores Supabase:
  - `SUPABASE_URL`
  - `SUPABASE_SERVICE_ROLE_KEY`
  - `GEMINI_API_KEY`
  - `ALLOWED_ORIGINS="http://localhost:3000"`
- [ ] `server/db.ts` foi substituído pela versão Supabase (ou está em processo)
- [ ] `package.json` atualizado com novas dependências
- [ ] `.env.example` atualizado (sem variáveis AWS, com Supabase)
- [ ] `.gitignore` verifica `.env*` (não commitando secrets)

### Testes locais
- [ ] `npm run lint` passa sem erros (type-check)
- [ ] `npm run dev` inicia sem exceções
- [ ] Frontend carrega em `http://localhost:3000`
- [ ] **Autenticação by header teste**: Abrir DevTools, tentar `/api/users` diretamente → deve retornar erro 401 (não lista de usuários)
- [ ] **Login Supabase Auth funciona**: Fazer login com `admin@racha.com` / `admin` → recebe JWT/token
- [ ] **Cadastro de jogador**: Criar novo jogador → salva no Postgres (verificar em Supabase SQL Editor: `SELECT * FROM players`)
- [ ] **Upload de mídia**: Fazer upload de imagem no mural → aparece em Supabase Storage (aba Storage no console Supabase)
- [ ] **Sorteio de times**: Se implementado, testa fluxo sorteio/resultado
- [ ] **Rate limiting**: Tentar fazer 6+ logins falhados seguidos → recebe erro 429 após 5 tentativas (ou conforme configuração)
- [ ] `npm run build` gera `dist/` sem erros
- [ ] `npm start` (modo produção local) roda e serve frontend + API na mesma porta

### Git e repositório
- [ ] Repositório Git está configurado (ou criado com `git init`)
- [ ] Arquivo `Dockerfile` commit (se não estiver, adicionar)
- [ ] Backup de `data/database.json` feito (se houver dados de produção anterior)
- [ ] `data/database.json` e `data/uploads/` removidos (ou estarão no `.gitignore` naturalmente)
- [ ] Todas as mudanças commitadas:
  ```bash
  git add .
  git commit -m "chore: migrate to Supabase + Render with security hardening"
  git push origin main
  ```

## ✅ DEPLOY (Configuração Render)

### Criar Web Service no Render
- [ ] Conta Render criada (ou conectar GitHub)
- [ ] Novo Web Service criado
- [ ] Repositório GitHub selecionado
- [ ] Branch: `main`
- [ ] **Build Command**: `npm run build` (Render vai chamar isso antes de `npm start`)
- [ ] **Start Command**: `npm start`
- [ ] **Plan**: Free (ou Starter se o free tiver limitações de cold start)

### Variáveis de Ambiente (Render Dashboard)
Na seção "Environment" do Web Service, adicionar:
- [ ] `GEMINI_API_KEY`: valor da chave Gemini
- [ ] `SUPABASE_URL`: ex: `https://xxxxxxxxxxxxx.supabase.co`
- [ ] `SUPABASE_SERVICE_ROLE_KEY`: a chave service role do Supabase
- [ ] `NODE_ENV`: `production`
- [ ] `ALLOWED_ORIGINS`: `https://<seu-dominio-render>.onrender.com` (Render atribui automaticamente)

### Deploy
- [ ] Web Service criado → inicia build automaticamente
- [ ] Build finaliza com sucesso (ver aba "Build Log" para erros)
- [ ] Serviço fica com status "Live" (não "Build Failed" ou "Crashed")
- [ ] URL pública atribuída (algo como `https://racha-do-fofim.onrender.com`)

## ✅ PÓS-DEPLOY (Verificação em produção)

### Acesso e navegação
- [ ] Abrir `https://<seu-dominio-render>.onrender.com` no navegador
- [ ] Página carrega sem erro 500
- [ ] Interface frontend visível
- [ ] Sem erros de CORS bloqueando requisições (abrir DevTools, aba "Network" → procurar por 403/CORS errors)

### Autenticação e segurança
- [ ] **Login funciona**: Fazer login com `admin@racha.com` / `admin`
- [ ] **Token JWT gerado**: Após login, verificar `localStorage` ou Network tab → campo `access_token` ou `token` presente
- [ ] **Header antigo não funciona mais**: Abrir DevTools, chamar `/api/users` sem token → erro 401 (não lista vazia)
- [ ] **Forjamento de `x-user-id` bloqueado**: Qualquer tentativa de hackear header recebe erro de autenticação
- [ ] **Rate limiting ativo**: Fazer 6+ tentativas de login falhadas seguidas → erro 429 (Too Many Requests)

### Persistência de dados
- [ ] **Criar novo jogador**: Preencher formulário, salvar → verifica se aparece na lista após refresh
- [ ] **Editar jogador**: Mudar um atributo (ex: nome), salvar → a mudança persiste após refresh
- [ ] **Deletar jogador**: Soft delete → jogador desaparece da lista, mas dados históricos são preservados
- [ ] **Criar fatura**: Gerar fatura manualmente (ou esperar cobrança automática mensal) → aparece na listagem de faturas
- [ ] **Pagar fatura**: Marcar fatura como paga → status muda e persiste
- [ ] **Listar histórico**: Consultas a dados passados (ex: resultados de partidas, jogadores deletados) retornam dados corretos

### Upload e Storage
- [ ] **Upload de imagem**: Fazer upload no mural → imagem aparece e é exibida
- [ ] **URL de upload é pública**: Copiar URL da imagem, abrir em aba anônima (sem autenticação) → imagem carrega (não erro 403)
- [ ] **Validação de tipo**: Tentar fazer upload de arquivo não-imagem (ex: `.txt`, `.html`) → erro "Formato de arquivo inválido"
- [ ] **Limite de tamanho**: Tentar upload de arquivo > 10MB → erro "Arquivo excede limite"

### Fluxos críticos
- [ ] **Sorteio de times** (se implementado): Confirmar partida → sortear times → ajustar manualmente → bloquear/finalizar sorteio → persiste
- [ ] **Fila de reservas**: Mensalista cancela → reserva é convocado → alerta é exibido e persiste
- [ ] **Financeiro**: Mensalidades são geradas automaticamente a cada mês (ou manualmente testado)
- [ ] **Mural**: Criar post, listar, destacar, remover → todas as operações persistem

### Logs e debugging
- [ ] **Sem erro 500**: Abrir aba "Logs" do Render (no dashboard) → nenhuma exceção não capturada visível
- [ ] **Sem erro de conexão Supabase**: Logs não mostram "Cannot connect to Supabase" ou erros de permissão
- [ ] **Sem erro de arquivo local**: Logs não mencionam `data/database.json` ou `data/uploads/` (aqueles resources foram removidos)

### Performance
- [ ] **Carregamento rápido**: Página inicial carrega em < 3 segundos
- [ ] **Sem cold start excessivo**: Se o Render.free tiver cold start, reacesso após 15 min inicializa < 30 segundos

## ⚠️ Rollback (Se algo der muito errado)

Se o deploy falhar irremediavelmente:

1. **Volta à versão anterior**: 
   ```bash
   git revert HEAD
   git push
   # Render re-deploya automaticamente
   ```

2. **Suspend Web Service no Render**: Dashboard → Web Service → Settings → "Suspend" (pausa enquanto você corrige)

3. **Recuperar dados do Supabase**: Supabase oferece backups automáticos (Database → Backups). Se os dados foram perdidos acidentalmente, contate suporte.
