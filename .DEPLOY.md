# .DEPLOY.md — Guia de Deploy "Racha do Fofim" para Render + Supabase

Este documento fornece um roteiro passo a passo para migrar o projeto de um setup local (arquivo JSON + disco local) para uma arquitetura de produção com Supabase (Postgres + Auth + Storage) e Render (hospedagem).

**Escopo**: substituir a camada de dados (banco, autenticação, uploads) e eliminar código legado de persistência em arquivo local. O frontend e a API REST continuam rodando no mesmo processo Node/Express.

**Tempo estimado**: 6-8 horas (se for a primeira vez com Supabase/Render). Decisões principais já foram tomadas; não há mais escolhas de arquitetura neste roteiro.

---

## Parte 1: Preparação e Setup Supabase

### Passo 1.1: Criar projeto Supabase

1. Acesse [https://supabase.com](https://supabase.com) e faça login (ou crie uma conta gratuita).
2. Clique em **"New project"**.
3. Preencha:
   - **Project name**: `racha-do-fofim` (ou nome à sua escolha)
   - **Database password**: Gere uma senha forte (ela será usada só para conexões do backend, não será exposta publicamente)
   - **Region**: Escolha a mais próxima (ex: `South America (São Paulo)` para melhor latência)
   - **Pricing plan**: Deixe no plano free
4. Clique em **"Create new project"** e aguarde ~2 minutos a criação do banco.
5. Uma vez criado, você será redirecionado ao dashboard. Guarde:
   - **Project URL** (algo como `https://xxxxxxxxxxxxx.supabase.co`)
   - **Anon Public Key** (você a verá em `Settings` → `API`)
   - **Service Role Secret** (use isto para o backend — clique em **"Service Role"** em `Settings` → `API`)

### Passo 1.2: Habilitar Supabase Auth

1. No dashboard do projeto, clique em **"Authentication"** (aba esquerda).
2. Já deve estar habilitado por padrão. Se não, clique em **"Enable Auth"**.
3. Configure **Email/Password** como método de login:
   - Vá para **"Providers"** → **"Email"**.
   - Certifique-se de que **"Email/Password"** está ativado (toggle verde).
4. Mantenha as configurações padrão por enquanto.

### Passo 1.3: Criar Storage bucket para uploads

1. No dashboard, clique em **"Storage"** (aba esquerda).
2. Clique em **"Create a new bucket"**.
3. Preencha:
   - **Bucket name**: `Uploads` (exatamente assim, com U maiúsculo — o nome do bucket é case-sensitive e precisa bater com o que o código em `server.ts` usa via `supabase.storage.from('Uploads')`)
   - **Public bucket**: ✅ **Sim** (para que as URLs geradas sejam públicas/acessíveis sem autenticação no GET)
4. Clique em **"Create bucket"**.

> **Nota técnica sobre os tipos escolhidos**: campos monetários e numéricos usam `DOUBLE PRECISION`/`INTEGER` em vez de `NUMERIC`/`DECIMAL` de propósito — o Supabase (via PostgREST) devolve colunas `NUMERIC` como **string** em JSON (para não perder precisão), o que quebraria silenciosamente somas e cálculos no código atual (`amount + amount` viraria concatenação de string). Todos os campos de data/hora usam `TEXT` em vez de `DATE`/`TIMESTAMP` para preservar exatamente o formato de string que o app já gera (`YYYY-MM-DD`, `HH:MM`, ISO 8601), evitando divergência de formato entre o que foi salvo e o que é lido de volta.

## Parte 4: Adaptar o Código Node

### Passo 4.1: Instalar dependências do Supabase

```bash
npm install @supabase/supabase-js helmet cors express-rate-limit file-type
```

- `@supabase/supabase-js`: Client do Supabase.
- `helmet`: Headers de segurança HTTP.

- `express-rate-limit`: Proteção contra brute-force.
- `file-type`: Validação de tipo de arquivo via magic bytes.

### Passo 4.2: Reescrever `server/db.ts` para usar Supabase

Substitua completamente o arquivo `server/db.ts` (que hoje usa arquivo JSON síncrono) por uma versão que use Supabase Postgres.

export async function ensureDbExists() {

// Funções específicas para cada tabela/operação
export async function getUser(userId: string): Promise<User | null> {
  const { data, error } = await supabase
    .from('users')
    .select('*')
    .eq('id', userId)
    .single();
  
  if (error) return null;
  return data;
}

export async function getAllUsers(): Promise<User[]> {

### Passo 4.3: Adaptar `server.ts` para I/O assíncrono e Supabase Auth

Este é o maior trabalho. **Mudanças principais**:

1. **Importar Supabase Auth e remover lógica de senha local**:
   ```typescript
   import { createClient } from '@supabase/supabase-js';
   import helmet from 'helmet';
   import cors from 'cors';
   import rateLimit from 'express-rate-limit';
   
   const supabase = createClient(process.env.SUPABASE_URL, process.env.SUPABASE_SERVICE_ROLE_KEY);
   ```

2. **Trocar autenticação por header solto por JWT do Supabase**:
   - **Antiga** (insegura): `x-user-id` header forjável.
   - **Nova**: JWT bearer token em `Authorization: Bearer <token>`, validado pelo Supabase.

3. **Adicionar middleware de segurança**:
   ```typescript
   app.use(helmet());
   app.use(cors({ origin: process.env.ALLOWED_ORIGINS || 'http://localhost:3000' }));
   app.use(rateLimit({ windowMs: 15 * 60 * 1000, max: 100 })); // Rate limit global
   ```

4. **Atualizar `/api/auth/login`**:
   - Trocar autenticação local por `supabase.auth.signInWithPassword(email, password)`.
   - Retornar o JWT gerado pelo Supabase.

5. **Atualizar `/api/auth/register`**:
   - Trocar por `supabase.auth.signUpWithPassword(email, password)`.
   - Criar record em `users` table automaticamente.

6. **Trocar upload local por Supabase Storage** (`/api/mural/upload`):
   ```typescript
   app.post('/api/mural/upload', async (req, res) => {
     const { filename, fileType, fileData } = req.body;
     
     // Validar magic bytes (não só extensão)
     const buffer = Buffer.from(fileData.replace(/^data:[^;]+;base64,/, ''), 'base64');
     const type = await fileTypeFromBuffer(buffer); // Usando lib 'file-type'
     
     if (!type || !['image/jpeg', 'image/png', 'image/webp'].includes(type.mime)) {
       return res.status(400).json({ error: 'Tipo de arquivo inválido.' });
     }
     
     // Upload para Supabase Storage
     const uniqueName = `${Date.now()}-${filename}`;
     const { data, error } = await supabase.storage
       .from('uploads')
       .upload(uniqueName, buffer, { contentType: type.mime });
     
     if (error) {
       return res.status(500).json({ error: error.message });
     }
     
     // Gerar URL pública
     const { data: { publicUrl } } = supabase.storage
       .from('uploads')
       .getPublicUrl(uniqueName);
     
     return res.json({ s3Url: publicUrl, localUrl: publicUrl });
   });
   ```

   const loginLimiter = rateLimit({

## Troubleshooting

### Erro: "Cannot GET /api/users"
**Causa**: Você está acessando a rota sem o JWT (token). Faça login primeiro e passe o token no header `Authorization: Bearer <token>`.

### Erro: "SUPABASE_URL is required"
**Causa**: Variável de ambiente não configurada no Render. Volte ao passo 7.4 e confirme que `SUPABASE_URL` está definido.

### Erro: "relation \"users\" does not exist"
**Causa**: Schema SQL do Supabase não foi criado (Passo 2.2). Voltea ao Supabase SQL Editor e rode o SQL de criação de tabelas novamente.

### Upload funciona localmente mas não no Render
**Causa**: Bucket do Supabase Storage não está público. Volte ao Supabase → Storage → Clique no bucket "uploads" → "Edit bucket" → Marque **"Public"** → Save.

### Render diz "Build failed"
**Causa**: Verifique os logs no Render (aba "Build Log"). Erros comuns:
- Falta de `package-lock.json`: Rode `npm install` localmente e faça commit de `package-lock.json`.
- Erro de TypeScript: Rode `npm run lint` localmente, corrija e faça commit.
- Falta de variáveis de ambiente: Confirme que as variáveis foram definidas no passo 7.4.
